# MCP specification delta: 2025-11-25 to 2026-07-28

The repository requires `mcp>=2.2,<3`, and `uv.lock` resolves `mcp` and
`mcp-types` to `2.2.0`. The server uses `MCPServer` over stdio. The
[specification changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)
and [Python SDK migration guide](https://py.sdk.modelcontextprotocol.io/migration/)
describe the protocol and SDK changes. The [migration report](SPEC-MIGRATION-REPORT.md)
has local validation commands and scope notes.

| Protocol change                                                                                                                                                 | Applicability to this server                                                                                                                                                                  |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Modern requests carry protocol version and capabilities in `_meta`, without `initialize` or MCP sessions; servers implement `server/discover`.                  | The SDK handles modern discovery and dispatch; the stdio server keeps no MCP session state. Downstream Smokeball OAuth state remains application state. Legacy negotiation is also exercised. |
| Results include `resultType`; list/read results include `ttlMs` and `cacheScope`.                                                                               | Discovery and tool, resource, and prompt results use `complete`; list/read results use zero TTL and private scope.                                                                            |
| Server capabilities can declare extensions.                                                                                                                     | No unused extension is advertised.                                                                                                                                                            |
| Tool schemas support JSON Schema 2020-12 and any JSON structured result.                                                                                        | The SDK generates schemas. Existing tool results remain strings; bounded list arguments appear in generated schemas.                                                                          |
| `tools/list` should be deterministic.                                                                                                                           | Registered tool order is checked across listings.                                                                                                                                             |
| Unknown resources use Invalid Params `-32602`. Reserved errors include header mismatch `-32020` and unsupported version `-32022`; unknown methods use `-32601`. | In-process protocol tests cover these reachable SDK responses.                                                                                                                                |
| Streamable HTTP POSTs use `Mcp-Method` and, for named methods, `Mcp-Name`.                                                                                      | An in-process SDK HTTP app tests routing headers. The shipped server uses stdio.                                                                                                              |
| HTTP resource subscription changes to `subscriptions/listen`; SSE resumability is removed.                                                                      | No HTTP transport, subscription publisher, or event store is exposed.                                                                                                                         |
| Server-initiated requests are replaced by multi round-trip requests; Roots, Sampling, and Logging are deprecated.                                               | No server-to-client requests or these optional features are used.                                                                                                                             |
| MCP authorization changes include issuer checks, issuer-bound credentials, and client registration metadata.                                                    | This process is neither an MCP authorization server nor an MCP OAuth client. Downstream Smokeball OAuth is separate.                                                                          |
| `_meta` defines trace-context keys.                                                                                                                             | The server has no custom MCP tracing integration.                                                                                                                                             |

SDK 2 supplies protocol types through `mcp-types`, runs synchronous handlers,
and places transport options on `run()` or app methods. This repository does
not implement a custom low-level MCP server, context, auth provider, or
client. The protocol tests exercise the SDK's modern and legacy clients.
